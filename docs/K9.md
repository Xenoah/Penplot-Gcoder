# EasyThreed K9：最初は紙に触れない

このアプリは **ファイルを生成するだけ**。純正 K9 の特定の基板・ファームウェア・ペン取付具での実機試験は行っていない。印刷で動いていた設定でも、ペン先・ホルダー・クリップを含む可動域は別。

**AT32 純正ファームの個体は、SD 再生が終わるとモーターを解放し得る。** 復旧用公開ダンプの通常終了処理はファイル外で `M84 X Y Z E` をキューに入れる。ペン上げを出力しても高さが保たれるとは限らない。電源を切った状態でも治具が安全なことを確認し、初回はペンを外して終了後まで見届ける。次の SD ジョブ前は座標を引き継がず、干渉しない状態で HOME と原点を確認する。

## 1. 測る

1. 加熱・押出を使わない。ノズル／ベッドが冷めた状態で紙を固定し、ペンと治具を原点復帰・全軸移動の妨げにならない位置に置く。ペンを外しても**ホルダーやノズル**は残るので干渉を確認する。
2. 本体で、メーカー指定の通常の手順で HOME。ホーム後の**機械座標系**を使う。手でキャリッジをずらしたり、モーター脱力後に座標が失われたりしたら再設定する。このソフトは機械の現在位置を取得しない。
3. 本体のジョグなど、動作が分かっている方法で、原点、XY の向き、実用範囲、Z の上限、紙に軽く触れる Z と十分に離れる Z を測る。Z が大きいほど紙から離れる方式のみ対応。上げ高さだけでなく、基準位置から最初にその絶対 Z へ動けることを確認する。
4. 機械設定に実測値を入れる。プロファイルの速度は **mm/s**、ファイルの F は **mm/min**（×60）。デモ値は保証値ではない。搬送・筆圧は実測に合わせ、バネ付きペンを使う場合も過大な押込みを避ける。
5. XY オフセット欄は取付寸法そのものではなく**指令補正量**。左下原点で `指令位置 = 描きたい紙面位置 + offset`。たとえばノズル基準でペンが +5 mm X にある場合、紙の x=20 mm を描くときの指令は x=15 mm、offset_x = −5 mm。中心原点ではこの変換後に各ベッド寸法の半分を引く。Z は `指令Z = 登録Z + offset_z`。同じ補正を二重に加えない。

## 2. 小さく、ペンを上げたまま試す

- `examples/alignment-card.svg` は実寸 **40 × 24 mm** の外枠。原寸を確認するなら Scale = 1 とし、X/Y で安全な中央近くに置く。`Fit` は拡大もするので、原寸テストには使わない。
- Studio の **Machine → Use K9** は手動 HOME 前提の出発点。値を編集後、**Export air run…** を選ぶ。CLI は `--air-run`。通常出力と XY の経路は同じだが、ペン下げ Z は一度も出力しない。
- 最初はペンを外してそばで監視する。SD に完全にコピーし、安全に取り外す。ファイル名例は短い ASCII の `AIRRUN.GCODE`。本体が認識しない場合は**その個体で実績のあるファイル名・拡張子・SD 形式**に照らして確認。認識可否や大文字必須は断定しない。
- ペンなしで全域とリフトが正しいことを確認し、ペン装着後もまず空走。想定外の動き・干渉があれば本体側で停止する。紙に描く `PLOT.GCODE` は最後。USB シリアル・SD の双方が読み取れる可能性のある基本命令に絞っているが、どちらも**当該個体の対応試験は未実施**。

- 公開 AT32 ダンプの通常開始処理では無条件の加熱や HOME は確認されなかったが、**停電復帰ルートには加熱復元や HOME がある**。ペン装着中に中断したジョブは復帰機能で再開せず、ペンを外してホームと設定を確認し直す。

## ファイルに含むもの／含まないもの

- ASCII の G21（mm）、G90（絶対）、G1（XYZ の必要な軸＋送り）、設定した場合の G4 P（待機）のみ。G28、G92、M84、ヒーター・押出・ファン・サーボ命令は出さない。
- 最初の位置決めの前と各独立ストロークの後にペンを上げ、最後の座標はペン上げ Z。終了時に原点へ戻さない。出力ファイルはモーターを解放しないが、ファームウェアの終了処理・タイムアウトは別。
- アプリは平面上のペン先と補正後のキャリッジ座標、Z、0.001 mm 丸め後の座標を検査する。ケーブル、固定金具、机との干渉や、実際の終端は検出しない。
- 所要時間は理想値で、現在位置不明の初回 XY/Z、加減速、制御待ちを含まない。

## Raspberry Pi / FAN / サーボ

PC で生成したファイルは Pi にコピーできる。既知の互換ホストがある場合は、まず**同じ空走ファイル**で確認する。純正 USB が G-code シリアル入力を受け付けるか、ボーレート、応答・再送規則は個体／ファーム依存。公開 AT32 ダンプの UART 初期化は 115200 bit/s。ポートが見えただけで対応とみなさない。電源を入れて確認する場合は、ノズルとベッドを冷ましたまま互換ホストで `M115` の応答を先に確認する。本版に USB 送信機能はなく、初代 Raspberry Pi B+（ARMv6）用実行ファイル・実機検証もない。

FAN 出力やサーボで Z の代わりにペンを上げる機構は別方式。出力ピン、駆動回路、電圧・電流、動作方向、対応ファーム命令、電源投入・異常時に安全側になることを確認するまでは有効化しない。Raspberry Pi の GPIO もプリンターの FAN 端子やサーボ用電源の代替として直接つながない。本版は **Z リフトのみ**であり、未確認の端子や任意 G-code テンプレートを実行しない。


## AT32 純正ダンプと照合した範囲

[コミュニティ公開の復旧用ダンプ](https://github.com/RecoverEasythreedK9/Dump-stock-Flash-Eeprom-Easythreed-K9-AT32)（AT32F403ARCT7 と 24C16）の読取り解析。ファームの書き換えは不要で、アプリには同梱しない。このダンプ 1 組に限り、実機の検証ではない。

- `G20` / `G21` はこのダンプでは単位を変えず、`G90` は絶対座標、`G1 F…` は mm/min、`G4 P…` は整数ミリ秒。
- EEPROM V37 は X/Y/Z = 606/606/600 steps/mm、最大 40/40/40 mm/s。この保存値はほかの個体の校正値ではない。最大送りは安全な描画速度を示すものでもない。
- 展開後 SHA-256: Flash `123ad0ea1d524104925e98f25232a9e20c4ee631872b0118089c00f17f36924c`、EEPROM `1ff9d5266546932549dcc98708b0b031745f0254c42414de53c4b2e66cbf748e`。
