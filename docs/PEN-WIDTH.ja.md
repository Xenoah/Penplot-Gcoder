# ペン幅で省略してから G-code を生成する（v0.12.0）

## 画像の細い線を省く

1. PNG/JPEGを取り込み、Importで **Ignore image details thinner than pen** をオン。
2. 実際のペン幅をmmで指定（0.05〜3 mm）。取り込みDPIから画素幅に換算し、その太さの円が収まらない細い部分を除いてから輪郭／中心線を抽出します。
3. プレビューを確認して **Add image**。ThresholdのOutline/Centerline、Clean line art、Color hatchに対応します。

長い細線も対象です。既存の **Minimum image stroke**（経路の長さによる除去）とは別の処理です。境界や枝の付け根は丸い形で残ることがあり、太さがちょうど閾値の線はできるだけ保持します。穴を埋める処理ではありません。

**幅は取り込み時のDPIに基づくサイズで判定します。** 抽出後に縮小・拡大しても元画像を再解析しません。最終寸法に合うDPIで取り込んでください。過去に取り込んだ画像には再取り込みが必要です。SVG/DXFや手描きの開いた中心線には元の線幅情報がないため、この画像除外は適用しません。画素より細い幅は画像から判別できません。

## 塗りの狭い部分を省く

- バケツの **ペン幅より細い部分を省く**：新規の塗りでは初期オン。斜線・クロスハッチの中心を外周と穴からペン半径ぶん離し、幅が足りない場所は描きません。水玉は従来どおり、ペンを含む水玉全体が入る場所だけに配置します。
- 通常のハッチは **Keep fill inside pen-width clearance** をオンにして幅を指定できます。
- 塗りの判定は配置・拡縮後の紙上mmで行います。輪郭描画をオンにしている場合、輪郭線自体は残ります。
- 旧プロジェクトの設定は自動でオンにしません。フィルターをオフにすると従来の経路になります。

## 生成 → プレビュー → 保存

1. 図と機械設定を確定。空走確認には **Air run** をオンにします。
2. **1. Generate G-code** を押すと、その時点の設定で生成してPreviewへ移動します。
3. **2. Preview** で実際の丸め済みG-codeの描画／移動経路とテキストを確認します。
4. **3. Export** で、その生成済みファイルを保存します。色別出力も生成後に有効になります。
5. 図・表示レイヤー・配置・機械条件を変えたら再生成が必要です。Air runのオン／オフ変更も再生成が必要です。プレビューに残した以前の結果は古いことを表示し、保存を無効にします。プロジェクト再読込後もGenerateから始めます。

CLI例（幅はmm）：

```sh
penplot convert --calibrated --dpi 254 --trace centerline --pen-width 0.3 -o PLOT.GCODE line.png
```

既存のK9のZ・速度・開始設定、手動ペン交換方式は変更しません。実際の線幅やにじみはペンと紙で異なるため、指定値は実際の描画結果から決めてください。
